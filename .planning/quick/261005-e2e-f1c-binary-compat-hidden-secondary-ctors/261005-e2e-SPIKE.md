## Variant K: compiler, detekt and Kotlin-language concerns

Measured on Kotlin 2.3.20, with the `@Suppress` annotations deliberately left off so that every raw
diagnostic would surface:

- **Compiler warnings:** none for `HandledByUiModel.kt` in either `compileDebugKotlin` or `compileReleaseKotlin`. Unused `mask` and `marker` parameters draw no warning, and neither does the `kotlin.jvm.internal` import. So the shim needs no `@Suppress`. The only `w:` lines in the build are the pre-existing ones in other files: EditorItemRow and the deprecated `Icons.Filled.*` in ExpandableFab and IconPickerGrid.
- **detekt:** no findings on the empty baseline. Why it passes today, and the risk if the rules change:
  - `LongParameterList` doesn't fire because `config/detekt-compose.yml` raises its thresholds to 18. The shims have 7 params (ctor) and 8 (copy). If the thresholds dropped back to the strict 6, both shims would trip it and need a declaration-scoped `@Suppress`.
  - `UnusedPrivateMember` doesn't flag a public `fun` inside a private companion.
  - `UnusedPrivateClass` is not enabled. If it were, it could flag the "unused" private companion.
- **The `$` identifier:** the Kotlin identifier is `legacyCopyDefault`. `$` appears only inside the `@JvmName("copy\$default")` string literal, so no Kotlin source identifier contains `$`. The JVM permits `$` in method names.
- **Dependence on synthetic naming:** K deliberately hand-reproduces the Kotlin compiler's default-argument ABI, meaning the name `copy$default`, the trailing `int mask` plus `Object` marker, and the ctor's `int` plus `DefaultConstructorMarker`. That ABI has been unchanged since Kotlin 1.0. More importantly, it IS the contract that v2.4.x consumers already link to, so K encodes no new assumption: the descriptors are frozen in their bytecode whatever future Kotlin versions emit. If a future Kotlin changed the scheme, our hand-written members would still match the old consumers, which is the point.
- **Clash risk with a future compiler-generated member:** low, and it fails loudly if it happens. The compiler emits `copy$default(H, <5 params>, int, Object)` only for a `copy` with exactly those 5 params AND at least one default value, which is variant R's hidden copy. The same goes for the `<init>(…, int, DefaultConstructorMarker)` ctor and a defaulted 5-param secondary ctor. If anyone later adds such a declaration, Kotlin reports a compile-time `Platform declaration clash`, just as R1 did. It cannot be a silent override. Data-class `copy` generation itself only ever emits the full-arity `copy$default`, which has a different descriptor.
- **Internal-package type in a signature:** `kotlin.jvm.internal.DefaultConstructorMarker` is a public stdlib class in an `internal` package.
  - It compiles with no warning or opt-in.
  - It appears only in the HIDDEN ctor, which is `ACC_SYNTHETIC` and absent from api.txt, Kotlin resolution and javac.
  - Every Kotlin-compiled binary already references this class, so removing it would break the whole ecosystem. It is as stable as the stdlib ABI.
  - `Any?` is not an option for that slot, because the descriptor must match exactly.
- **Private-companion side effects:**
  - The class gains a package-private `HandledByUiModel$Companion` class (`0x0030`) and a private static `Companion` field (`0x001a`).
  - It also gains a public synthetic `Companion(DefaultConstructorMarker)` ctor, standard for private companions. The class is package-private, so it is not consumer ABI.
  - Metalava ignores all of it.
  - Compose stability is unaffected, since the companion is static.
  - A data class may have only one companion. If one of these classes ever needs a public companion, the shim must move into it, and that companion must stay `private`, or the shim must become a `@JvmStatic` member of the public companion while still `HIDDEN`. None of the six classes has a companion today (checked).
- **`@JvmStatic` in a private companion:** the outer static bridge keeps the function's own visibility, which is public. The `ACC_SYNTHETIC` flag comes from `HIDDEN`. That gives `0x1019` versus v2.4.1's `0x1009`. The only difference is ACC_FINAL, which means nothing on a static method for `invokestatic`.
- **Semantic-drift risk (the real cost of K):** K hand-decodes the mask per slot. A wrong bit index, or a forgotten `self.<appended prop>`, would compile and silently misbehave. The mitigation is the plan's per-class reflection tests, which use all-defaults masks, explicit-value masks and fully non-default originals. On HandledByUiModel those tests passed. R gets this right by construction, because the compiler generates the decode.

/**

 * A consumer compiled against v2.4.x calls `<init>(<v2.4.1 params>, int, DefaultConstructorMarker)`
 * or the static `copy$default(self, <v2.4.1 params>, int, Object)` when it omits defaulted
 * arguments. These tests resolve that exact descriptor reflectively and invoke it with a v2.4-style

 *
 * Deliberately no overload-count or exact-arity assertions: Phase 17 may add members.

class DataClassBinaryCompatShimTest {

    private fun defaultCtor(cls: Class<*>, vararg v241Params: Class<*>): Constructor<*> {
        val ctor = cls.getDeclaredConstructor(
            *v241Params,
            Int::class.javaPrimitiveType,
            DefaultConstructorMarker::class.java
        )
        assertTrue(JModifier.isPublic(ctor.modifiers))
        return ctor
    }

    private fun copyDefault(cls: Class<*>, vararg v241Params: Class<*>): Method {
        val method = cls.getMethod(
            "copy\$default",
            cls,
            *v241Params,
            Int::class.javaPrimitiveType,
            Any::class.java
        )
        assertTrue(JModifier.isPublic(method.modifiers))
        assertTrue(JModifier.isStatic(method.modifiers))
        return method
