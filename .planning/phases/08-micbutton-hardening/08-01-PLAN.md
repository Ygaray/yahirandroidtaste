<objective>
Harden `MicButton` (CalTracker Phase-64 findings, WR-01/WR-02/IN-01/IN-02) so it is fully
consumer-agnostic and callback-correct, ready for SecondBrain to adopt: parameterized microcopy
with generic neutral defaults, latest-callback safety via `rememberUpdatedState`, hub-vocabulary
KDoc, and sensible parameter defaults — all backward-compatible with existing call sites.

Purpose: `MicButton` currently hardcodes CalTracker-specific microcopy and calls `onTap`/
`onDisabledTap` directly inside a long-lived gesture coroutine, so a callback identity swapped in
mid-press can be silently dropped. Both are reusability/correctness defects that block a second
consumer (SecondBrain) from adopting the component as-is.
Output: `MicButton.kt` with parameterized descriptions + `rememberUpdatedState`-routed callbacks +
hub-vocabulary KDoc; `MicButtonGestureTest.kt` with a RED→GREEN mid-press callback-identity
regression test; a regenerated, additive `api.txt`.
</objective>

<threat_model>
This is a UI-only library change with no network, storage, or auth surface — the only new inputs
are caller-supplied plain-text `String` parameters (rendered as accessibility `contentDescription`
text) and two `rememberUpdatedState`-routed callback references. Neither crosses a
privilege/trust boundary in the traditional sense: the "caller" here is trusted app code linking
this library, not an untrusted network peer, and none of this phase's changes touch dependencies,
persistence, or any credential.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Caller code -> `MicButton` parameters | Caller-supplied `String`s (description overrides) and lambdas (`onTap`/`onDisabledTap`) cross into library rendering + gesture-dispatch code. Caller is trusted app code (CalTracker/SecondBrain), not attacker-controlled input. |
| Compose runtime -> Android Accessibility Services | Rendered `contentDescription` text is exposed as plain text to any active accessibility service (e.g. TalkBack) — read-only exposure, no markup/code execution. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-08-01 | Tampering | `MicButton`'s `onPress` release-time dispatch (`onTap`/`onDisabledTap`) | medium | mitigate | Task 1 routes both callbacks through `rememberUpdatedState` (D-03) so release-time dispatch always reads the current closure, preventing a stale mid-press closure from firing the wrong branch — e.g. a consumer's permission-gated `onDisabledTap` path being silently skipped if a stale `onTap` fired instead. Proven by a RED-then-GREEN regression test that swaps callback identity mid-press with two observably distinct counters (guards against a vacuous pass). |
| T-08-02 | Information Disclosure | `disabledDescription`/`tapToTalkDescription`/`listeningDescription` parameters | low | accept | These are plain caller-supplied UI strings rendered only into Android's accessibility tree — no markup/HTML parsing, no code execution, no persistence, no network transmission. The library performs no validation because none is meaningful for a plain-text accessibility label; the caller owns any wording/localization policy. |
| T-08-03 | Tampering (API surface) | `api.txt` / public `MicButton` signature | low | accept | The additive signature change (new defaulted params, defaulted `enabled`/`onDisabledTap`) is verified empirically by `apiCheck` (D-02, Task 3) to be a backward-compatible metalava delta; no existing caller can be broken by a parameter it does not pass. |

No new dependencies are added by this phase, so the package-legitimacy gate does not apply.
Spoofing/Repudiation/Denial-of-Service/Elevation-of-Privilege categories are not applicable beyond
T-08-01 above: there is no identity to spoof, no audit log to repudiate, and no resource exhaustion
surface in a single Compose button.
</threat_model>
