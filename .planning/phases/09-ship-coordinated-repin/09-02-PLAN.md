<threat_model>
This plan reads a public, unauthenticated third-party build service (JitPack) over HTTPS and
edits this repo's own documentation file -- there is no secret handling and no consumer repo is
touched.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| This repo -> JitPack (public network) | Read-only GET requests confirming a public artifact resolves; no credentials sent. |
| repin_status.py script -> ECOSYSTEM.md | The script owns and rewrites only the text between the repin-matrix markers; hand-edits in this plan are confined to the surrounding prose. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-09-04 | Tampering | JitPack resolution check | medium | mitigate | Task 1 cross-checks BOTH the raw artifact HTTP status AND the JitPack builds-API JSON (status/isTag) with bounded retry, so a lazy-build 404 is retried rather than silently treated as success or failure. |
| T-09-05 | Tampering | ECOSYSTEM.md machine-owned matrix block | low | mitigate | Task 2's action is scoped explicitly to the prose surrounding the markers; the reconcile script itself refuses to run without the markers intact, and re-running it would overwrite any accidental hand-edit inside them. |
| T-09-06 | Repudiation | ECOSYSTEM.md edit authorship | low | accept | Standard git commit attribution already covers this; no new audit surface is introduced. |

No new dependencies are added by this phase, so the package-legitimacy gate does not apply.
Spoofing/Information-Disclosure/Denial-of-Service/Elevation-of-Privilege are not applicable beyond
the above: no identity is spoofed, no secret is disclosed, and no resource-exhaustion surface
exists in a bounded-retry read-only check plus a documentation edit.
</threat_model>
