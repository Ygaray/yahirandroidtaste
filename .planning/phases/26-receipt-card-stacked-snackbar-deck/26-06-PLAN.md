<objective>
Close the single Gate-1 failure of Phase 26 (self-UAT cycle 1 of 3): a peek tap that lands on a back card's Undo runs Undo instead of fanning the deck (`26-05-SELF-UAT.md`, criterion 3, FSTK-04). Four of five criteria passed on the tester; this plan changes nothing else.

Root cause, confirmed on the tester (tree `26`/`27`, log `28`/`29`, control `30`): in a collapsed deck a back card's Undo button is composed, measured and hit-testable like on any card. The Undo's layout starts 8dp below its card's top edge (`FeedbackCardRow` top padding) and Compose widens a button's touch region by up to 4dp (the accessibility sliver the tester reported starts about 3.9dp above that layout top), so the button reaches into the 14dp strip, which is the only part of a back card the user can touch (the front card covers the rest). The button's clickable consumes the down and the up before the card's single tap owner (the only caller of `onPeekTap`) can see a tap, so the tap resolves the card `Undone` (on the consumer's tracked path the undo lambda runs and the entry becomes `Undone`) and the deck stays collapsed. The strip itself looks blank, because the Undo label sits below it. The suite stayed green because `tapStrip` clicks the strip at its horizontal centre, never over an Undo.

Runtime decision (per D-06 [peek-target] amended, "separate pointer and semantics paths"; nothing else is re-decided): on a collapsed back card the pointer path is the peek tap and nothing else, and the semantics path (open, Undo, Dismiss, the separate Undo child) is untouched. The Undo is therefore still composed and rendered (same look, D-01 [card-layout], D-02 [undo-button]) but cannot take touch: a transparent, semantics-free sibling placed above the card's content while `collapsedBack` is true takes the hit instead (Compose gives the topmost sibling with pointer input the hit and stops looking at the siblings below it, while every ancestor still receives the same events; the Material3 Surface relies on the same rule), so the card root's single tap owner sees an ordinary unconsumed tap and fans.

Alternatives considered and rejected, so a later reader does not retry them:
- Not rendering the Undo on a collapsed back card (D-02 look kept instead): removes the separate focusable Undo child that Gate-1 SC5 verified in the collapsed tree, and re-lays the row out while the fan spring runs (the Undo column takes up to 40 percent of the row, so the body width, the wrapping and the card height would change). The visible design (a blank strip; only the locked 0.9 and 0.75 alpha ghost of a deeper card shows through) is unchanged, and there is no strong reason to change it.
- Disabling the Undo (`enabled = false`): Compose then reports the node as disabled (TalkBack announces it dimmed) and the colours change; the semantics must stay identical (A11Y-01).
- Routing the Undo button's click to `onPeekTap`: that one lambda also serves TalkBack's double tap, so a screen-reader user activating the Undo child would fan the deck instead of undoing.
- A second tap owner or an Initial-pass tap handler in the card: breaks the one-owner rule pinned by `FeedbackStackSourceContractTest` (T-26-10).

Decisions honored, none reopened: D-01 [card-layout] row and clamp unchanged; D-02 [undo-button] Undo stays `DynamicActionButton` Text emphasis; D-03 [long-hold] long hold still does nothing; D-04 [pause-scope] the deck-wide observer still sees every touch; D-05 [swipe] draggable gating unchanged; D-06 [peek-target] amended, this plan applies it; D-07 [live-region] semantics unchanged; D-08 [fanned-overflow] untouched.

Purpose: FSTK-04 (ROADMAP SC3: tapping the peek of a collapsed deck fans it so every card's body and Undo can be tapped) holds for the gesture the criterion names, wherever on the strip it lands, and FSTK-02, FSTK-03, FSTK-05, FSTK-06 and A11Y-01 stay as verified.
