# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** This phase's UI surface is one thing — a tier badge (`Primitive` | `Pattern`)
rendered on two existing surfaces of the `ExplorerActivity` gallery: `ComponentRow` (list/search)
and `ComponentDetailScreen`'s header. Per D-02/CONTEXT.md, it reuses Material3 `Badge` — no new
component is introduced. This contract is deliberately narrow; it does not touch the rest of the
gallery's or library's existing visual language, which stays as-is.

## Spacing Scale

Confirmed: the module already has an established, granular dp scale in `theme/Dimens.kt`
(multiples of 4, with two named exceptions). This phase reuses existing values — it does not add
a new spacing token.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding (existing, `Dimens.ContentSpacing`/`Dimens.AccentSpineWidth`) |
| sm | 8px | **This phase:** gap between the title `Text` and the tier `Badge`, on both `ComponentRow`'s headline and `ComponentDetailScreen`'s `TopAppBar` title row. Also existing `Dimens.TopPadding`/`Dimens.ChipToTitleGap`. |
| md | 16px | Row/screen horizontal padding — existing (`Dimens.HorizontalPadding`), unaffected by this phase. |
| lg | 24px | Section padding — existing, unaffected. |
| xl | 32px | Layout gaps — existing, unaffected. |
| 2xl | 48px | `Dimens.TouchTarget` — not applicable to the badge (the badge is non-interactive/non-tappable, see UI Considerations). |
| 3xl | 64px | Not used in this phase. |

Exceptions: `Dimens.HairlineSpacing` (2px) and `Dimens.HairlineBorder` (1px) are pre-existing,
documented exceptions to the 4px grid — neither is touched or newly introduced by this phase.
The tier badge itself introduces no new exception: its internal padding comes from Material3's
own `BadgeDefaults`, which this contract does not override.

## Typography

Scoped to what this phase touches or sits directly beside (all values already declared in
`theme/Type.kt` — no new type scale is introduced):

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label (badge text) | 11px (`labelSmall`) | Medium (500) | 16px (1.45) |
| Body (`ComponentRow` headline/supporting, unaffected, adjacent to badge) | 16px (`bodyLarge`) / 14px (`bodyMedium`) | Normal (400) | 24px / 20px (1.5 / 1.43) |
| Heading (`ComponentDetailScreen` `TopAppBar` title, unaffected, adjacent to badge) | 22px (`titleLarge`) | Medium (500) — explicit `fontWeight = FontWeight.Medium` override on the existing `Text(entry.name, ...)` call, not the `SemiBold` set in `Typography.titleLarge` | 28px (1.27) |
| Display | not applicable | — | — |

**Badge text style:** Material3 `Badge`'s content slot applies `labelSmall` internally via
`BadgeDefaults` — do not pass an explicit `style` override; let the component's own default apply.
This keeps the badge visually distinct (smaller) from the row/title text it sits beside, which is
the correct "badge, not label" weight per Material3 convention.

**Weight count check:** exactly 2 distinct weights appear across everything this phase touches —
Normal (400, body text) and Medium (500, badge text + the title's explicit override). No new
weight is introduced.

## Color

The badge visually distinguishes the two tier values using two Material3 color **roles the theme
already declares** (`theme/Color.kt`) — no new color is added.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `NeutralBgLight` `#F5FAFB` (light) / `InkBackground` `#0B1F1E` (dark) | Screen/list background — existing, unaffected. |
| Secondary (30%) | `surfaceContainer`/`surfaceContainerLow` (`#E8EFF0` light / `#152927` dark) | Row/card surfaces — existing, unaffected. |
| Accent (10%) | `TealPrimary` `#006875` (light) / `TealPrimaryDark` `#53D7E9` (dark) | **Not used by the tier badge.** Reserved exclusively for its existing role: `SectionLabel` text, the FAB, and other primary/active-interaction affordances. The badge deliberately does **not** compete for the primary accent's meaning — see rationale below. |
| Destructive | `ErrorRed` `#BA1A1A` (light) / `ErrorRedDark` `#FFB4AB` (dark) | Not used this phase — no destructive action is introduced. |

### Tier badge color mapping (this phase's actual color contract)

| Tier | Container color | Content (text) color | Rationale |
|------|-----------------|----------------------|-----------|
| `PRIMITIVE` | `MaterialTheme.colorScheme.secondaryContainer` (`SlateSecondaryContainer` `#CCE8EE` light / `#334B50` dark) | `onSecondaryContainer` | Slate reads as the neutral/foundational tier — matches "primitive = zero domain nouns, caller-content-only" (D-03). |
| `PATTERN` | `MaterialTheme.colorScheme.tertiaryContainer` (`AmberTertiaryContainer` `#FFE0A0` light / `#563D00` dark) | `onTertiaryContainer` | Amber is the theme's existing "opinion/emphasis" hue (already used for favorite/star tint) — matches "pattern = encodes an opinion/composition/interaction convention" (D-03). |

Reusing `secondaryContainer`/`tertiaryContainer` (already-declared M3 roles) rather than
introducing a bespoke badge color keeps the change additive and avoids a third meaning competing
for the primary Teal accent, which stays reserved for interactive/primary emphasis only.

Accent reserved for: `SectionLabel` text color, the FAB, active/pressed interactive states, and
other existing primary-emphasis uses — **never** the tier badge (explicit non-goal of this
contract, to prevent accent-color meaning collision).

## Component Placement & Interaction (this phase's actual contract)

Beyond the generic sections above, the concrete placement/behavior contract the executor should
implement:

1. **`ComponentRow`** (`ExplorerIndexScreen.kt`): add a `tier: ComponentRegistry.Tier` parameter.
   Change `headlineContent` from a bare `Text(name)` to `Row { Text(name); Spacer(8dp); Badge { Text(tierLabel) } }`.
   Do **not** use the currently-unused `leadingContent` slot for the badge — keep that slot free
   (it may carry a future icon), and do not disturb the existing `trailingContent` chevron. All
   call sites of `ComponentRow` (index search results + every family screen's row list) must pass
   `entry.tier`.
2. **`ComponentDetailScreen`**: change the `TopAppBar`'s `title` from
   `Text(entry.name, fontWeight = FontWeight.Medium)` to a `Row { Text(entry.name, fontWeight = FontWeight.Medium); Spacer(8dp); Badge { Text(tierLabel) } }` — mirrors the list-row pattern for
   visual consistency between the two surfaces (D-02's requirement that both surfaces show tier).
3. **Interaction state:** the badge is **non-interactive** — no click handler, no ripple, not
   wrapped in `Modifier.clickable`. Clicking anywhere on the row still triggers the row's existing
   `onClick` (navigate to detail) exactly as before; the badge does not intercept touch.
4. **Accessibility:** tier is conveyed by **text**, not color alone (the badge's `Text` content is
   always `"Primitive"` or `"Pattern"`) — this already satisfies "don't rely on color alone."
   No tooltip or long-press affordance is needed since the label is always visible, never
   icon-only.
