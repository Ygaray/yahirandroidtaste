<objective>
Deliver `NeedsConfirmation` -- the third, purely additive sealed arm of `VoiceOutcomeUiState`
(VOUT-04) -- rendered by the ALREADY-SHIPPED `OutcomeSheet` composable: a reason string,
single-or-batch proposed items, and confirm/cancel actions, domain-neutral so it covers BOTH
SecondBrain's `MutationGate`/`VoiceConfirmGate` destructive risk confirm AND CalTracker's weak-match
single/batch confirm, with zero library-side change between the two (D-03/D-05/D-06). Per D-02
(re-confirmed live against Phase 11's shipped `VoiceOutcomeUiState.kt` this session's research), this
is additive-only: `Success`/`Failure` are never reshaped.

This plan leads with a tracer (Task 1): the full `NeedsConfirmation`/`ProposedItemUiModel`/
`SelectionMode` model shape plus `OutcomeSheet`'s new private body functions, wired end-to-end and
proven on SB's single-item destructive path. Task 2 expands the SAME render functions to also cover
CT's batch path (shared `topLevelContent`, per-item `onRemove`), the full edge-coverage set (adjacency,
empty/single, opaque-id, ordering), and closes the phase with the full verification suite.

Purpose: apps map SB's risk-confirm subjects and CT's weak-match single/batch results onto ONE prop
shape with no per-consumer library change (A2/E1).
Output: `NeedsConfirmation` sealed arm, `ProposedItemUiModel` + `SelectionMode`, `OutcomeSheet`'s
extended rendering, two Explorer gallery fixtures, a green full suite (tests + detekt + apiCheck).
</objective>
