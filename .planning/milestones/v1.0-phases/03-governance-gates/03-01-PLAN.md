<objective>
Fix the additive-guard pre-commit hook's root-cause false-flag (GOV-03): `tools/verify-additive-diff.sh`
diffs a stale release tag against the *working tree* (cumulative since the tag), so any `src/main`
rewrite that has ever landed since the last tag poisons every later commit — including a pure
`.planning/`-only one — into lane 2. Per locked decision D-01 (03-CONTEXT.md), replace that basis
with the commit's own staged delta (`git diff --cached` vs `HEAD`, scoped to `src/main`), regression-
test the exact reproduced bug shape at the pre-commit-hook level, and explicitly track — with a live-
reproduced test, not just a comment — the sibling `verify-api-additive.sh` script's identical
architectural flaw (currently dormant only because the baseline tag predates `api.txt`; RESEARCH.md
Open Question 1 scopes today's fix to `src/main` only, per D-01's literal `∩ src/main` text, and
recommends this residual risk be tracked rather than silently left for Phase 5's first tag-cut that
includes `api.txt`).

Purpose: A contributor (including this project's own doc/planning commits) should never need to know
about or invoke `HUB_LANE_OVERRIDE` for a `.planning/`/docs-only change again.
Output: A corrected `verify-additive-diff.sh`, its own fixture test updated to match the new staged-
delta semantics, a new end-to-end regression case in `tools/test/test-precommit-hook.sh` reproducing
the original bug's exact commit sequence, a new characterization test in
`tools/test/test-verify-api-additive.sh` proving the sibling script's latent bug under simulated
future conditions, and a tracked note in STATE.md.

  <files>tools/verify-additive-diff.sh, tools/test/test-verify-additive-diff.sh</files>
  <action>
    In `tools/verify-additive-diff.sh`, replace the single-ref working-tree diff (currently
    `git diff -U0 "$BASELINE_COMMIT" -- "${PATHS[@]}" > "$TMP_DIR/full.diff" || true`) with a
    staged-vs-HEAD diff: `git diff --cached -U0 -- "${PATHS[@]}" > "$TMP_DIR/full.diff" || true`.
    Per D-01, this diffs the INDEX (what the current commit is about to add) against `HEAD`, not a
    stale tag against the whole working tree — a commit touching nothing in `src/main` becomes
    unconditionally clean, with no dependency on how long ago the last tag was cut. Keep
    `BASELINE_COMMIT` as the parameter used ONLY for the default `PATHS` enumeration
    (`git ls-tree -z -r --name-only "$BASELINE_COMMIT" -- src/main`, unchanged) and for the
    ref-resolution fail-loudly check (unchanged) — do not touch the path filter (RESEARCH.md
    Anti-Pattern: the bug is the comparison basis, not path scope, and `src/main`-only path scoping
    is already correct). Leave the `normalize()` + `comm -23` reconciliation logic (untouched) — it
    already handles the legitimate trailing `+`/`,` false-rewrite case and needs no change.

    This changes the script's semantics: it no longer compares against arbitrary history since
    `BASELINE_COMMIT`, it compares the INDEX against `HEAD`. Update
    `tools/test/test-verify-additive-diff.sh`'s cases (a) and (b) to `git add -A` immediately before
    invoking `"$SCRIPT" v0.0.0` (case (a): after the append + new-file edit; case (b): after the
    `sed -i` rewrite of `src/main/B.kt`) — under the new staged-delta basis, an unstaged working-tree
    edit produces an empty `git diff --cached` and would trivially (and wrongly) pass, so these
    fixtures must stage their edits to keep testing the real invariant. Case (c) (doc-file rewrite
    outside `src/`) needs no staging change — `NOTES.md` is outside `src/main`'s default `PATHS` so
    it is never in the diffed set regardless of staged status; verify it still passes unmodified.
