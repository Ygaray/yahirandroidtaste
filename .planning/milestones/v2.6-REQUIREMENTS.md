# Requirements: yahirandroidtaste — Milestone v2.6

**Defined:** 2026-10-11
**Core Value:** An agent building one of Yahir's apps finds the widget it needs already here, coherent and legible, and drops it in instead of writing a new one.
**Milestone goal:** Ship library `v2.6.0`, an additive, opt-in minor: a "Receipt" rendering of the voice outcome sheet plus the atoms it needs, and the full key lifecycle on `ProviderKeyCard`. Every default reproduces today's pixels (SecondBrain stays on Classic, unchanged).
**Scope source:**

- Decision record: `.planning/seams/v2.6.0-SKETCH.md` (`105255d`). CT and SB signed it off with no signature deltas; the P1-P3 rulings are applied.
- CT `76-UI-SPEC.md` § "YAT Evolution Asks", Y-1..Y-15 (`0a1da128`).
- SB `.planning/cross-repo/178-XR-01.md`.
- Teamlead dispatch, 2026-10-11.

**Rules for every requirement:**

- **Source compatibility only.** New params and fields have defaults. No new `@Deprecated(HIDDEN)` overloads, hand-written old-arity `copy`, hidden ctors or `copy$default` shims (P1).
- **New behavior uses new enums.** No existing enum gains constants.
- **Strings come from the caller.** Every user-visible string is a caller-supplied param; English defaults only where the hub already has the precedent.
- **No consumer specifics.** No consumer nouns, colors or types in the hub. The hub defaults warn to `tertiaryContainer`/`onTertiaryContainer`, and consumers pass their own tokens.
- **Param placement.** Composable params are appended after `modifier`, or inserted before a trailing lambda (never after one). `NeedsConfirmation` fields go before `onConfirm`/`onCancel`.

## Milestone v2.6 Requirements

### Tone foundation & atoms

- [x] **VTONE-01**: `theme/` exposes `@Immutable class ToneColors(container, content)` (value equality), `ToneDefaults.error()` (`errorContainer`/`error`) and `ToneDefaults.warn()` (`tertiaryContainer`/`onTertiaryContainer`), both resolved from the active `ColorScheme`, plus `enum class ContentTone { Default, Muted, Warn, Error }` (Y-1). The KDoc tells consumers to pass their own tokens when dynamic color makes `tertiary` non-amber.
- [x] **VBTN-01**: `DynamicActionButton` gains `emphasis: ActionButtonEmphasis? = null` and `icon: ImageVector? = null`, with a new `enum class ActionButtonEmphasis { Filled, Tonal, Text, TextSmall }`. `role` picks the hue and `emphasis` picks the widget, per the Y-8 specs. `TextSmall` keeps a 48dp touch target. With `emphasis = null` and `icon = null`, the role→widget mapping is exactly today's (Y-8).
- [x] **VBTN-02**: A new `RoundIconButton(icon, contentDescription, onClick, modifier, enabled = true, size = 40.dp)`: a circle with a 1dp `outlineVariant` border, a transparent container and a 20dp `onSurface` icon, inside a 48dp touch target (Y-8).
- [x] **VBAR-01**: A new `StackedProgressBar(segments: List<BarSegment>, trackColor: Color, modifier, height = 6.dp)` with `@Immutable data class BarSegment(fraction, color)`. Segments draw left to right, clamp so the sum is ≤ 1 (negative fractions clamp to 0) and clip to a fully rounded track. `trackColor` is required (Y-9).
- [x] **VCARD-01**: A new `ToneCard(tone: ToneColors, modifier, content: ColumnScope.() -> Unit)`: a `Surface` on `tone.container`/`tone.content` with 12dp corners, 12dp × 16dp padding and children spaced 4dp. The default tones give content-on-container contrast ≥ 4.5:1 (Y-10).
- [x] **VCHIP-01**: A new `PillChip(label, onClick, modifier, leadingIcon = null, trailingIcon = null, enabled = true, contentDescription = null)`: 32dp tall, full radius, 1dp `outlineVariant` border, a transparent container, a single-line `bodySmall` label, 18dp icons and a 48dp touch target. `AppChip` and `PresetChip` are unchanged (Y-12).

### Rows, selectors & sheet frame

- [x] **VROW-01**: A new stateless `ReceiptRow` with the sketch's Y-2 signature and layout:
  - **Summary:** a `Row` of a title column (weight 1f; title, subtitle, supporting content, cue pill), a value column (wraps, min 56dp, end-aligned), a chevron (only when `onClick != null && trailingAction == null`), then `trailingAction`.
  - **Overflow:** title, subtitle and value are single-line with ellipsis. When space runs out, the value wins and the title ellipsizes. This is verified with a long localized title at 360dp.
  - **Expanded content:** `expandedContent` renders full width below the summary.
  - **Cue pill:** 4dp × 8dp padding, 24dp tall, on `warnTone`.
  - **Chevron:** rotates 0→180° in 200ms.
  - **`dimmed`:** 38% alpha plus strikethrough, with a 200ms fade.
  - **Collapsed height:** with all lines and no cue, 92dp ±1dp.
- [x] **VROW-02**: `ReceiptRow` semantics. The summary is one merged node containing title, subtitle, value, caption and cue. When `onClick != null` it is `clickable(role = Button, onClickLabel)` with an expanded/collapsed `stateDescription` from the caller labels. `trailingAction` and `expandedContent` stay separate nodes. The hub ships no accordion logic; single-open state is the consumer's, shown in an Explorer demo (Y-2).
- [x] **VSEG-01**: `SegmentedOptionSelector` gains `disabledOptions: Set<Int> = emptySet()` and `style: SegmentedOptionStyle = SegmentedOptionStyle.Material`, with a new `enum class SegmentedOptionStyle { Material, Pill }`.
  - **Pill:** one full-radius outlined container. The selected segment is `primary`/`onPrimary` with no check icon. Labels are single-line `bodyMedium` with ellipsis, 40dp tall.
  - **Disabled options:** a disabled option renders at 38% alpha and never fires; the others stay enabled.
  - **Default:** `Material` with an empty set is exactly v2.5.1, including the G-15-1 layout. The KDoc warns that long localized labels truncate in Pill (Y-11).
- [x] **VSHEET-01**: `SheetScaffold` gains `shape: Shape = BottomSheetDefaults.ExpandedShape`, inserted before the trailing `content` lambda. The default keeps the M3 28dp shape (Y-13).

### Receipt outcome sheet

- [x] **VRCPT-01**: `OutcomeSheet` gains `style: OutcomeSheetStyle = OutcomeSheetStyle.Classic` and `colors: OutcomeSheetColors = OutcomeSheetDefaults.colors()`. New types:
  - `enum class OutcomeSheetStyle { Classic, Receipt }`;
  - `OutcomeSheetColors(warnTone, errorTone)`;
  - `OutcomeSheetDefaults.colors(...)` and `OutcomeSheetDefaults.ReceiptTitleStyle`.

  Classic runs today's code path unchanged; the 3-arg call compiles and renders as in v2.5.1, which code review and Robolectric state assertions prove (P3). Receipt implements the Y-3 frame:
  - 24dp top corners via `SheetScaffold(shape)`;
  - a title row with badge, title and `titleActions`, plus a transcript line;
  - a pinned action bar for NeedsConfirmation and Failure, under a 1dp divider, with the start action at 16dp and the end action at 368dp in a 384dp-wide sheet;
  - Success actions at the end of the scroll content;
  - the v2.4.1 `weight(1f, fill = false)` body, so the bar never starves.
- [x] **VRCPT-02**: `NeedsConfirmation` gains `confirmEnabled: Boolean = true` and `titleActions: (@Composable () -> Unit)? = null`, inserted before `onConfirm`. While `confirmEnabled = false` the confirm node is `enabled = false` and `onConfirm` never fires. In Receipt:
  - `reason` renders as the transcript;
  - the start action is `cancelLabel` (Text);
  - the end action is `confirmLabel` (Filled, hue from `severity`).

  The KDoc documents that `items` may be empty when `topLevelContent` renders the rows (Y-4).
- [x] **VRCPT-03**: `Success` gains:
  - `badge: OutcomeBadge? = null`, `titleActions = null`, `startAction: SheetActionUiModel? = null` and `endAction: SheetActionUiModel? = null`;
  - new `enum class OutcomeBadge { Success, Reverted, Error, Warn }` (Reverted uses `Icons.AutoMirrored.Filled.Undo`);
  - new `data class SheetActionUiModel(label, onClick, emphasis, enabled = true, icon = null, role = Neutral, activeWhileInFlight = false)`.

  Receipt order: title row → handled-by pill → `editableContent` → `batchResults`/`undo` → the actions row. `inFlight` disables every action except those with `activeWhileInFlight = true`, so SB can show an in-flight Cancel. Classic ignores the new fields (Y-5 + SB dispatch note 3).
- [x] **VRCPT-04**: `Failure` gains:
  - `title = null`, `transcript = null`, `tone: FailureTone = FailureTone.Error`, `tip = null`, `secondaryAction: SheetActionUiModel? = null` and `badge: OutcomeBadge? = null`;
  - new `enum class FailureTone { Error, Warn }`;
  - `FailureActionUiModel` gains `icon: ImageVector? = null`.

  In Receipt:
  - the title row sits outside the card;
  - the card is a `ToneCard` holding `reason` plus `body`;
  - the tip renders under the card;
  - `action` moves to the end of the pinned bar (Filled, keeping its role hue);
  - `secondaryAction` is at the start.

  Classic keeps today's card and honors `FailureTone.Warn` by painting `colors.warnTone`. The default Error is unchanged (Y-6).
- [x] **VRCPT-05**: `HandledByUiModel` gains `prefixLabel: String = "Handled by"` and `onDevice: Boolean = false`.
  - **Receipt** renders a pill: `surfaceContainerHighest`, full radius, 4dp × 12dp padding, `bodySmall`. It shows a 6dp dot (`primary`, or `warnTone.content` when `onDevice`), then `"{prefixLabel} "`, then the tier in SemiBold, then `" · {approach/provider/model}"`.
  - **Text check:** `tier = "Local grammar", provider = "offline", onDevice = true` renders "Handled by Local grammar · offline".
  - **Classic:** `HandledByRow` is unchanged (Y-7).
- [x] **VTAG-01**: Receipt nodes expose the Y-14 stable test tags:
  - `outcome_sheet_title`, `outcome_sheet_badge`, `outcome_sheet_title_actions`, `outcome_sheet_transcript`;
  - `outcome_sheet_action_bar`, `outcome_sheet_action_start`, `outcome_sheet_action_end`;
  - `outcome_sheet_failure_surface`, `outcome_sheet_failure_tip`, `outcome_sheet_handled_by`;
  - `receipt_row_summary`, `receipt_row_trailing_action`, `receipt_row_expanded_content`;
  - `stacked_progress_bar`, `tone_card`, `round_icon_button`, `pill_chip`.

  The Receipt NeedsConfirmation bar keeps the existing `outcome_sheet_confirmation_cancel`/`_confirm` tags, and Classic tags are unchanged. A test asserts each tag in each Receipt state. The hub never sets `testTagsAsResourceId`.
- [x] **VXR-01**: The refused/partial undo surface on `OutcomeSheet` carries `liveRegion = LiveRegionMode.Assertive`, so TalkBack announces it when it appears (XR-178-01 a). This is semantics only, with no visual change.
- [x] **VXR-02**: `VoiceOutcomeUiState.Failure` gains `undo: UndoAffordanceUiModel? = null`, rendered by the same undo block as `Success` in both styles (XR-178-01 b). SB can then retire its local `FailureUndoBody`.

### Key lifecycle & undo center

- [x] **VKEY-01**: `ProviderKeyCard` gains the sketch §1 key-lifecycle params, all appended after `providerLabel`: `savedKeys: Map<String, SavedKeyUiModel> = emptyMap()`, `editingSavedKey: Boolean = false`, `actions: ProviderKeyActions? = null` and `labels: ProviderKeyLabels = ProviderKeyDefaults.labels()`.
  - **Field:** the single key field follows `selectedProviderId`.
  - **Saved key:** when a key is saved for the selected provider and you're not editing, the field is replaced by a summary showing the fingerprint only ("Saved · sk-ant-…abcd"), plus Update | Clear.
  - **No saved key:** otherwise you get the field plus Save, and Cancel when `onCancelEdit != null`.
  - **Actions:** `inFlight` disables all of them.
  - **Default:** with an empty `savedKeys` and `actions = null`, the card is exactly today's, so SB is unchanged.
- [x] **VKEY-02**: Each provider keeps its own saved key: switching providers shows that provider's summary or field. Providers present in `savedKeys` get `labels.savedMarker` in the dropdown. The raw key never renders anywhere. Stable tags: `provider_key_saved_summary` and `provider_key_action_{save,update,clear,cancel}`.
- [x] **VUNDO-02**: `UndoCenterScreen` can render a group row for entries that share an `UndoHistoryStore` group: the group label, member count and status, with an "Undo all" that invokes a caller callback. This takes optional params inserted before the trailing `onClear`. The default is today's flat list (XR-178-01 c).

## Out of Scope

| Feature | Reason |
|---------|--------|
| Binary-compat shims (hidden old-arity overloads, `copy$default`, hidden ctors) | P1. The charter is source compatibility only, because consumers recompile on every repin |
| Roborazzi / screenshot golden tests | Declined by Yahir (2026-10-11). Parity is proven structurally plus by Robolectric assertions; Receipt by the owner's screencap review |
| Accordion / one-open-at-a-time logic in the hub | Consumer state (Y-2); the hub row is stateless |
| CT's macro line, Calories copy, warn color values, white/black track rule, `VoiceItemEditor` | App composition and app tokens passed into hub params (CT UI-SPEC "Out of scope for the hub") |
| Key persistence, validation network calls, or storage in `ProviderKeyCard` | The card stays presentational. The consumer owns persistence (INV-01) |
| A VAE transaction-bracketing hook (XR-178-01 d) | Not a hub item. It's informational, with no ask |
| Repinning SB/CT | Consumer channels plus the teamlead's §11 ledger. The hub never edits consumer files |
