<threat_model>
This plan touches only build-time configuration (a metalava exclusion rule) and this repo's own
tracked signature/documentation files -- there is no runtime user input and no new dependency. The
one meaningful trust boundary is the tag cut itself, which this plan deliberately stops short of.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| build.gradle.kts config -> tracked api.txt baseline | A build-time config change reshapes what gets committed as the public-API contract; no runtime input crosses this boundary. |
| This plan -> the immutable v2.2.0 tag / published JitPack artifact | The step that changes what every consumer can resolve. Explicitly not crossed by this plan -- it stops at a human-gated checkpoint. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-09-01 | Tampering | metalava `hiddenAnnotations` config / api.txt rebaseline | medium | mitigate | Scoped to exactly one annotation FQN (`dagger.internal.DaggerGenerated`); Task 1's four verify checks separately confirm the generated symbol is gone AND that UndoHistoryStore's real class/ctor/extension survive untouched, guarding against the config accidentally hiding real public API. |
| T-09-02 | Tampering (supply-chain) | The immutable `v2.2.0` tag / published JitPack artifact | high | mitigate | A `checkpoint:decision` with `gate="blocking-human"` sits before any tag action, so it stops for a human in every mode including auto-mode; every gate (tests, detekt, both apiCheck variants, drift guards, mavenLocal publish) must be green on the exact commit before the checkpoint is even reached; this plan's last task explicitly surfaces the command rather than running `git tag`/`git push` itself. |
| T-09-03 | Tampering (secrets) | The tag-cut and push command | low | accept | The command uses only this developer's existing git remote credentials (already used for every other push to this public repo); no new secret or credential is introduced or handled by this plan. |

No new dependencies are added by this phase, so the package-legitimacy gate does not apply.
Spoofing/Repudiation/Denial-of-Service/Elevation-of-Privilege are not applicable beyond the above:
there is no identity to spoof, no audit log to repudiate, and no resource-exhaustion surface in a
config fix plus a verification battery.
</threat_model>
