- PD-1 [in-flight, Open Question 1]: while `Success.inFlight` is true the row is locked (alpha 0.38, chevron kept, no click action, no `Role.Button`) and unlocks when it turns false. Why: a still-running write may not have created the item yet, and `inFlight` already disables every other interactive control of the sheet (CR-02). - PD-2 [Classic branch]: the Classic open path is an if/else INSIDE the existing scaffold lambda, not the research's separate early-return branch with its own scaffold. - PD-3 [tags]: the new test tags are `open_target_row` and `open_target_chevron`. - PD-5 [blank fallbacks]: a null or blank `targetLabel` falls back to `summary`, a blank `targetDetail` draws nothing, a blank `openLabel` falls back to the row title as the click label.
- PD-6 [double tap, Pitfall 10]: no library debounce. The handler must be idempotent; KDoc says so. Flagged FA-2.
- PD-7 [docs, Open Question 5]: no API.md, STYLE.md or INTEGRATION.md edit in Phase 27 (SHIP-05 in Phase 29 owns them; counts do not move because no public composable is added). KDoc carries the contract.
