# YAT v2.6.0: signature sketch (step 1, no code)

**Status:** sketch for teamlead review. There is no milestone, no build and no code yet.
**Base:** `v2.5.1` (`b6c363c`), `api.txt` at HEAD.
**Inputs:**
- (A) CT `76-UI-SPEC.md` § "YAT Evolution Asks", Y-1..Y-15 (OD-1).
- (B) The ProviderKeyCard key-lifecycle widget Yahir approved on 2026-10-10.

**Release shape:** a minor release. It is additive and opt-in. Every new param has a default that reproduces today's pixels, so SecondBrain stays on Classic, unchanged, and recompiles with no edits.

Package placement follows the hub: composables go in `component/`, UI models in `model/`, and tone tokens in `theme/`. Every new public `@Composable` gets registered in a family screen (drift guard).

---

## 0. Compatibility mechanics (applies to every ask)

| Kind of change | How it lands (source-compatible) |
|---|---|
| Composable gains params | Params are appended **after** `modifier` and before a trailing `content` lambda if there is one. Each has a default. |
| Data class gains fields | Fields are appended with defaults. `NeedsConfirmation` is the one exception: its fields go **before** `onConfirm`/`onCancel`, because both are required lambdas and both consumers pass every arg by name (checked: SB `VoiceConfirmSheetModels.kt:29`, CT `VoiceOutcomeMapper.kt:315/435`). |
| New behavior axis | Gets a **new** enum. No existing enum gains a constant, so consumer `when`s still compile. |
| Old-arity overloads / `copy$default` / hidden ctors | **None added** (see Pushback P1). |

## 1. API-key widget: `ProviderKeyCard` owns the full key lifecycle (B)

Today's signature stays a prefix. Six new params are appended; each defaults to the off state.

```kotlin
@Composable
fun ProviderKeyCard(
    providers: List<ProviderOptionUiModel>,
    selectedProviderId: String?,
    onProviderSelected: (String) -> Unit,
    keyValue: String,
    onKeyChange: (String) -> Unit,
    keyState: KeyFieldState,
    keyLabel: String,
    modifier: Modifier = Modifier,
    emptyProvidersReason: String = /* unchanged */,
    providerLabel: String = /* unchanged */,
    // --- v2.6.0, all off by default ---
    savedKeys: Map<String, SavedKeyUiModel> = emptyMap(),   // providerId -> saved key (fingerprint only)
    editingSavedKey: Boolean = false,                       // true = show the field even though a key is saved
    actions: ProviderKeyActions? = null,                    // null = no button row (today)
    labels: ProviderKeyLabels = ProviderKeyDefaults.labels(),
)

@Immutable data class SavedKeyUiModel(val fingerprint: String)   // e.g. "sk-ant-…abcd"; never a raw key

@Immutable data class ProviderKeyActions(
    val onSave: () -> Unit,
    val saveEnabled: Boolean = true,
    val onUpdate: (() -> Unit)? = null,   // null hides Update
    val onClear: (() -> Unit)? = null,    // null hides Clear
    val onCancelEdit: (() -> Unit)? = null,
    val inFlight: Boolean = false,        // disables every action while saving
)

@Immutable data class ProviderKeyLabels(
    val save: String = "Save",
    val update: String = "Update",
    val clear: String = "Clear",
    val cancel: String = "Cancel",
    val savedPrefix: String = "Saved",   // renders "Saved · sk-ant-…abcd"
    val savedMarker: String = "saved",   // dropdown suffix for providers that have a saved key
)
object ProviderKeyDefaults { fun labels(...) = ProviderKeyLabels(...) }
```

**Behavior:** the card stays stateless. The consumer owns persistence and the typed text.
- The single key field always follows `selectedProviderId`.
- If `savedKeys[selected] != null && !editingSavedKey`, the field is replaced by a saved-key summary: check icon + `"{savedPrefix} · {fingerprint}"`, then Update | Clear.
- Otherwise the field renders as today, followed by Save (and Cancel when `onCancelEdit != null`).
- Each provider keeps its own key: switching providers shows that provider's summary or field.
- Providers present in `savedKeys` get `savedMarker` appended in the dropdown.
- Buttons are `DynamicActionButton`s: Save is the `Save` role, Clear is `Destructive`, Update and Cancel are `Neutral`.

**Default (today's pixels):** `savedKeys` is empty and `actions` is null, which is exactly today's card. SB keeps its own Save row and is untouched. CT can then delete its dead dropdown (`onProviderSelected = {}`) and its Save/Cancel and `ApiKeyConfigured` rows, and pass the real provider list.

**Stable tags:**
- `provider_key_saved_summary`
- `provider_key_action_save`
- `provider_key_action_update`
- `provider_key_action_clear`
- `provider_key_action_cancel`

- **Error color:** `errorTone` is not a param. `ContentTone.Error` resolves through `ToneDefaults.error()`.

## 3. Pushbacks

**P1. No new `@Deprecated(HIDDEN)` overloads, hand-written old-arity `copy`, hidden ctors or `copy$default` shims.** This contradicts both the teamlead brief and CT's "Binary compat" rule.
- The hub's charter (`CLAUDE.md`, `API.md` § Compatibility rule, Yahir-approved memory `yat-source-compat-not-binary`) is source compatibility only. Both consumers recompile on every repin, and there are no prebuilt binaries to keep linking.
- Shims are dead weight: about 12 extra hidden members across six data classes and four composables.
- Shims are also a known defect source. INC-2026-10-05-02 F1c was a shim bug.
- The v2.5.0 shims stay.
- If the teamlead or Yahir really wants binary compat for v2.6.0, that's a charter change, and Yahir should decide it explicitly rather than have it arrive with a feature ask.

**P2. `verify-api-additive.sh` no longer exists.** It was retired in Phase 19 (STATE.md D-03). What it checked was replaced as follows:
- The source-level gate is `./gradlew apiCheck` against an `api.txt` regenerated **before** the cut (the stale-apitxt lesson still applies).
- `bash tools/test/run-all.sh` covers additive-diff, the lane classifier and the hook.
- `tools/verify-binary-abi.sh v2.5.1` is informational. Exit 3 is expected once params are appended, and it doesn't block.
- "api.txt additive" can't mean a literal append-only text diff. Appending a defaulted param rewrites that function's signature line.

  **Proposed cut gate:**
  - no public symbol removed;
  - no required param added to an existing member;
  - existing enums keep their constants;
  - a **v2.5.1 call-site canary**: today's SB and CT call shapes plus the Explorer compile unchanged against v2.6.0 (a test source set in the hub).

**P3. "Pixel-identical to v2.5.1" golden tests (Y-3, Y-8).** The hub has no screenshot infrastructure: no Roborazzi or Paparazzi in `build.gradle.kts`.

  **Proposal:**
  - Prove Classic and `emphasis = null` parity structurally. The defaulted path calls the **same unchanged private composables**, which the code review checks. Robolectric semantic, bounds and color assertions pin each Classic state.
  - Pixel parity for Receipt goes through the Y-15 owner screenshot review.
  - Adding Roborazzi is possible, but it's a new tooling dependency, so it should be a separate opt-in decision and not hidden inside v2.6.0.

**P4. Scope and phasing (not a rejection).** One ask set like this is roughly 6 new public composables, 7 new types and 9 widened signatures. I'd cut it as ~4 phases:
1. Tone foundation + atoms: Y-1, Y-8, Y-9, Y-10, Y-12.
2. `ReceiptRow` + selector + sheet shape: Y-2, Y-11, Y-13.
3. Receipt `OutcomeSheet`: Y-3..Y-7, Y-14.
4. ProviderKeyCard lifecycle + Explorer/docs + cut: B, Y-15.

CT's "blocked" plans wait on the whole tag either way, so the order inside the milestone doesn't change their timing.

**Minor deviations, already folded into the signatures above:**
- `AutoMirrored` Undo icon (Y-5).
- Classic honors `FailureTone.Warn` (Y-6).
- ±1dp tolerance on the 92dp height test (Y-2).
- Negative `BarSegment` fractions clamp to 0 (Y-9).
